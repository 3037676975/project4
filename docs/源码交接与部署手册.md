# KnowFlow 源码交接与部署手册

更新日期：2026-08-25  
适用版本：KnowFlow v24 及以后
线上站点：https://ai-kb-saas-guide-2026.drewlaurence4549.chatgpt.site

## 1. 交付内容

源码包包含：

- Next.js / Vinext 前后端完整源码。
- Cloudflare Worker、D1、R2 配置与全部数据库迁移。
- 企业知识库、RAG、Embedding、Rerank、OCR 和 Qdrant 接口。
- 企业注册、独立账号密码、成员权限和三套后台。
- 微信支付、支付宝、兼容网关的商户配置与回调处理。
- 官网客服、企微、公众号、钉钉和飞书渠道代码。
- Linux / Windows 私有化测试脚本与 Docker Compose。
- Docling / RapidOCR 文档解析服务。
- Infinity / BGE-M3 Embedding 服务。
- 测试、构建、初始化和运营巡检脚本。

源码包不包含可重新安装的 `node_modules`、构建产物、Git 历史和临时缓存。

## 3. 本次版本重点

### 3.1 官网与登录体验

- 官网改为珍珠白、雾紫和薄荷青的浅色磨砂玻璃设计。
- 超级管理员、内部管理员和企业成员登录入口统一视觉，但地址、角色校验和跳转完全分离。
- 三个登录入口均支持账号密码与“滑块 + 邮箱验证码”两种方式；只有超级管理员控制台显示后台切换入口。
- 企业后台继续突出企业名称和企业专属工作区。
- 已有后台卡片、经营趋势、健康度、成本和质量范围做了轻量可视化。

### 3.2 系统资料显隐

超级管理员进入：

`平台控制台 → 系统资料`

可以控制以下内置资料是否显示：

`AI客服知识库SaaS开源选型与实现手册_2026.pdf`

- “显示”只决定企业账号能否在知识库列表看到该文档。
- “应用”独立决定质量测试、官网客服和客户 API 是否检索该文档。
- 支持隐藏但应用、显示但不应用；关闭不会删除文档和向量，重新开启即可恢复。
- 企业自己上传的资料完全不受影响。

### 3.3 质量测试范围

企业进入 `质量测试`，可以临时选择任意属于当前企业的知识库。

- 交互式测试和标准题批量测试使用同一个选择。
- 临时选择不会修改正式客服助手绑定。
- 服务端验证知识库所属租户，不能跨企业检索。

### 3.4 平台统一模型服务

超级管理员进入：

`平台控制台 → 模型服务`

- DeepSeek、Embedding、Rerank、OCR 的地址、模型与密钥只允许超级管理员维护。
- 企业后台不再显示密钥表单；企业成员只能看到服务就绪状态并正常使用。
- 服务端拒绝企业 Owner / Admin 手工调用模型配置保存和连接测试接口。
- 升级后首次进入该页面，会优先从当前超级管理员原来所属企业接管已有加密配置；无需重新填写密钥。
- 原 `tenant_provider_configs` 记录暂时保留用于兼容和回滚；平台配置生效后优先读取 `platform_provider_configs`。
- 平台修改 Embedding 模型、地址或维度会把全部企业文档标记为待重建，避免新旧向量混用。

## 4. Linux 一键部署

### 4.1 环境要求

- 推荐 Ubuntu 22.04 / 24.04。
- Docker Engine 24 以上。
- Docker Compose v2。
- 至少 4 核 CPU、8 GB 内存、30 GB 可用空间。
- 首次下载 BGE-M3 模型需要联网。

### 4.2 启动

解压源码，进入项目目录：

```bash
unzip KnowFlow-v21-full-source.zip
cd ai-kb-saas-guide-2026
bash scripts/init-private.sh
```

脚本会：

1. 生成 `.env.private`。
2. 生成本地超级管理员随机密码。
3. 生成配置加密、会话、OCR、Embedding、Qdrant 等随机密钥。
4. 构建并启动 KnowFlow、Qdrant、Docling/RapidOCR、Infinity/BGE-M3。
5. 自动执行尚未应用的 D1 数据库迁移。

启动完成后访问：

`http://服务器IP:3000/platform/login`

默认账号：

`admin@local.test`

初始密码显示在终端，并保存在项目根目录的 `.env.private`。首次登录后系统要求修改密码。

### 4.3 常用命令

```bash
docker compose --env-file .env.private -f docker-compose.private.yml ps
docker compose --env-file .env.private -f docker-compose.private.yml logs -f knowflow
docker compose --env-file .env.private -f docker-compose.private.yml restart
docker compose --env-file .env.private -f docker-compose.private.yml down
```

升级源码后：

```bash
docker compose --env-file .env.private -f docker-compose.private.yml up -d --build
```

不要删除 `.env.private` 和 Docker named volumes，否则可能丢失密钥或本地数据。

## 5. Windows 测试部署

### 5.1 环境要求

- Windows 11 或 Windows Server 2022。
- Docker Desktop，启用 WSL2。
- PowerShell 7。
- 至少 8 GB 内存，建议 16 GB。

### 5.2 启动

在 PowerShell 中进入源码目录：

```powershell

```

完成后访问：

`http://localhost:3000/platform/login`

Windows 版本建议用于开发测试；正式私有化生产环境优先使用 Linux。

## 7. 模型与 OCR 配置

超级管理员进入 `平台控制台 → 模型服务`。企业工作台不提供密钥配置入口：

| 能力 | 推荐配置 |
|---|---|
| 生成模型 | DeepSeek OpenAI 兼容接口 |
| Embedding | `BAAI/bge-m3`，1024 维 |
| Rerank | `BAAI/bge-reranker-v2-m3` |
| 自建 OCR | Docling + RapidOCR |
| 云 OCR | 百度智能云或腾讯云 |
| 向量库 | 小规模 D1；大型知识库使用 Qdrant |

修改 Embedding 模型、地址或维度后，系统会把全部企业文档标记为待重建；各企业需要在对应知识库执行“全部重建”。

知识库上传区提供三种识别模式：

- 智能判断：文本型 PDF、Excel 等优先原生解析，扫描件自动 OCR。
- 强制文字 OCR：处理图片和逐页扫描 PDF。
- 表格结构化 OCR：百度 `table` 或腾讯 `RecognizeTableOCR`，保留单元格行列并转为 Markdown 表格。

原生 XLSX 直接解析单元格，不消耗云 OCR 次数；Word、Excel、PPT 的复杂版式建议使用 Docling。

升级已有数据库时，迁移 `0012_left_kat_farrell.sql` 会创建平台模型配置表。超级管理员首次打开“模型服务”会自动复制原加密密文和密钥提示，复制过程不解密、不改变密钥内容，并记录平台审计日志。你以前已经填写的 DeepSeek、Embedding、Rerank 与 OCR 密钥不会因入口移动而丢失。

## 8. SMTP、滑块与邮箱验证码

超级管理员进入 `平台控制台 → 邮件服务`，统一配置 SMTP；企业和内部管理员看不到授权码。

QQ 邮箱推荐参数：

| 项目 | 值 |
|---|---|
| SMTP 主机 | `smtp.qq.com` |
| 端口 | `465` |
| SSL | 开启 |
| STARTTLS | 关闭 |
| 用户名 / 发件邮箱 | 完整 QQ 邮箱 |
| 密码 | QQ 邮箱生成的 SMTP 授权码，不是 QQ 登录密码 |
| 验证码 | 6 位、10 分钟过期、60 秒重发、最多 5 次 |

托管站点通过 Cloudflare TCP Sockets 直接连接 465/587；25 端口不允许。私有化栈内置 Python SMTP 中继作为回退。注册流程必须先完成滑块才能发送邮箱验证码；验证码校验成功后才创建企业账号。邮箱验证码登录使用相同的一次性消费、过期、重发与失败次数控制。

## 9. 数据备份与迁移

源码 ZIP 只包含程序，不等于线上业务数据备份。完整迁移应同时保存：

1. 源码 ZIP。
2. D1 数据库导出。
3. R2 原始文档。
4. Qdrant 向量快照。
5. `.env.private` 或线上运行环境变量。

企业管理员可以在企业工作台的渠道与合规区域执行租户一键导出与恢复。导出内容包括租户记录、知识库配置、历史租户模型配置密文和 R2 文件。平台统一模型配置不属于任何单个租户，必须随完整 D1 数据库一起备份。

私有化部署还应备份 Docker volumes：

```text
knowflow-state
qdrant-data
docling-cache
infinity-cache
```

账号密码只保存不可逆哈希，无法从数据库还原明文；服务商 API Key 使用配置加密密钥保护。迁移时必须同时保留原 `CONFIG_ENCRYPTION_KEY`，否则旧密文无法解密。

## 10. 支付上线检查

超级管理员进入 `支付商户`：

1. 微信支付填写商户号、AppID、证书序列号、APIv3 密钥、商户私钥和平台公钥。
2. 支付宝填写 AppID、应用私钥和支付宝公钥。
3. 复制异步通知地址到支付平台。
4. 保存后执行签名校验。
5. 使用最低金额完成一次正式付款。
6. 检查支付回调、订单履约、Credits、套餐续期与退款。

未完成真实支付验收前，保持沙箱或关闭状态。

## 11. 上线验收清单

- 官网、三个登录入口和移动端布局正常。
- 超级管理员、内部管理员、企业成员不能越权。
- 系统资料“显示”和“应用”两个开关可以独立组合。
- 上传 TXT、PDF、Word、Excel 和图片均能解析；扫描 PDF 与表格 OCR 分别验收。
- 注册必须先通过滑块，邮箱验证码能够真实送达并且只能使用一次。
- 三个登录入口不能互相切换角色；企业/内部管理员直接访问 `/platform` 会被服务端拒绝。
- 文档状态显示向量索引就绪，chunks 大于 0。
- 质量测试能自主选择知识库。
- 不同表达方式可以命中正确资料。
- 低于可靠度阈值时明确拒答。
- Rerank 失败时可以回退，不中断客服。
- 官网客服能留下线索并创建人工工单。
- 模型、OCR、Credits 与毛利记录正常。
- 支付回调经过验签、金额校验和幂等处理。
- 备份导出后可以在测试租户恢复。

## 13. 安全交接

- 不把 `.env.private` 提交到 Git。
- 不在聊天、日志或截图中公开完整 API Key。
- 正式环境为 DeepSeek、硅基流动、百度、腾讯和支付平台创建独立子账号或最小权限密钥。
- 交接后立即轮换所有曾经外发的密码与 API Key。
- 定期验证数据导出、恢复和 Qdrant 快照。
- 对外开放前配置 HTTPS、域名白名单、限流、日志留存和隐私说明。
